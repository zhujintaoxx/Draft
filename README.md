# Draft

## 项目现状（给新同学）

目前仓库是一个**极简初始化状态**：

- 只有一个 `README.md` 文件。
- 还没有看到业务代码目录（如 `src/`、`app/`、`backend/`、`frontend/` 等）。
- 也没有依赖管理和构建文件（如 `package.json`、`pyproject.toml`、`go.mod`、`Cargo.toml` 等）。

这通常意味着：

1. 项目还在 very early stage（占位仓库）。
2. 或者代码尚未 push 到当前分支。
3. 或者这是专门用于草稿/讨论的仓库。

## 现在能确认的“整体结构”

```text
Draft/
└── README.md
```

## 新人最该优先了解的内容

在当前信息下，建议按下面顺序快速确认：

1. **项目目标是什么**
   - 这是产品代码仓库，还是文档/草稿仓库？
2. **主分支是否有完整内容**
   - 看看 `main` / `master` / 其他活跃分支是否有真实代码。
3. **技术栈和启动方式**
   - 确认将来会使用什么语言、框架、数据库、部署方式。
4. **协作规范**
   - 分支策略、提交规范、代码评审规则、发布流程。

## 后续学习建议（从 0 到 1）

### 第 1 周：建立全局认知

- 先阅读仓库内所有文档（目前只有 README）。
- 找项目负责人确认：
  - MVP 范围
  - 里程碑
  - 近期优先级

### 第 2 周：补齐工程骨架

建议尽快补齐基础工程文件（由团队决定技术栈后实施）：

- 代码目录（如 `src/`）
- 依赖与构建配置
- `CONTRIBUTING.md`
- `docs/architecture.md`
- 基础 CI（lint + test）

### 第 3 周：形成“可运行最小闭环”

- 一个最小可运行模块
- 一个测试样例
- 一条自动化校验流水线

## 给新同学的实操 checklist

- [ ] 拉取并确认默认分支
- [ ] 查看所有远端分支和最近提交历史
- [ ] 与维护者确认项目定位
- [ ] 确认技术选型与目录规范
- [ ] 跑通第一个“Hello World”版本
